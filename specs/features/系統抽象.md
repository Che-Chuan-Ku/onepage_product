# 系統抽象（BDD Analysis Phase 03）

## Boundary
| Boundary | 定義 |
|----------|------|
| web-backend | Spring Boot REST API + PostgreSQL（落子驗證、勝負判定、帳號/戰績/歷史） |
| realtime | STOMP over WebSocket（對局狀態廣播、開局同步、聊天）— 由 backend 權威驅動 |

伺服器權威（Server-authoritative，需求 #20）：所有落子與勝負判定必經後端，前端僅呈現。

## 4 種抽象測試角色對應
| 角色 | Gherkin 位置 | 本專案實作 |
|------|-------------|-----------|
| States Prepare | Given | 直接注入 players / games / moves / rooms 狀態 |
| Operation Invocation | When | 呼叫 REST 端點（落子、開局、選擇、配對等） |
| Operation Result Verifier | Then | 驗證回應（成功/錯誤訊息、JWT、回放資料） |
| States Verify | Then | 驗證 DB 狀態（棋盤、回合、戰績、房間成員） |

## 核心抽象實體
- Player（registered / guest）
- GameRoom（status 狀態機：WAITING → READY → IN_PROGRESS → FINISHED）
- Game / GameSession（status：OPENING → PLAYING → FINISHED；Swap2 開局子流）
- Move（不可變落子事件，15×15，0..14）
- OpeningStone（Swap2 開局子，可悔最後一子）

## 事件對照（來源 CSV「相關事件/狀態機」欄）
PlayerRegistered, PlayerLoggedIn, RoomCreated, PlayerJoinedRoom, PlayerReadyToggled,
AllPlayersReady, CoinTossCompleted, Swap2OpeningStarted, OpeningStonePlaced,
Swap2ChoiceMade, ColorAssignmentFinalized, OpeningCompleted, MovePlaced,
GameStateUpdated, WinConditionMet, GameDraw, GameEnded, InvalidMoveRejected,
PlayerDisconnected, PlayerReconnected, LocalGameStarted, SpectatorJoinedRoom

> SpectatorJoinedRoom（Q5 觀戰機制衍生）：觀戰者加入房間時觸發；觸發來源為對戰席已滿時加入房間者自動成為觀戰者。

## 句型模型（最小必要集）
- Command 失敗句型：`When <操作> / Then 操作失敗，錯誤為 "<訊息>"`
- Command 成功句型：`When <操作> / Then 操作成功 / And <狀態驗證/事件>`
- Query 句型：`When 查詢 <資源> / Then 操作成功 / And 查詢結果應包含：<datatable>`
- 即時廣播句型：`Then 系統發布 <Event> 事件 [And 廣播給雙方]`
