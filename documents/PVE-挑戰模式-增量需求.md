# PVE 挑戰模式 — 增量需求文件

> 版本：v1.1（2026-07-07，經一輪 fresh-agent 明確性審查後修正）
> 用途：作為需求增量的輸入文件。設計脈絡與決策理由見同目錄《PVE-小丑牌模式-設計指引.md》，本文件只放「要做什麼」的明確需求。
> 所有數值為初始可調參數（實作時必須外部化為設定，不得寫死），但驗收以本文件數值為準。

---

## 1. 增量目標

在現有五子棋對戰平台上新增**單人 PVE「挑戰模式」**：玩家在限定手數內，以「完成連線造成傷害」的方式擊破每關 Boss HP，連續通過 8 關；關與關之間透過商店購買遺物與技能強化構築（roguelike run 結構）。

## 2. 名詞定義

| 名詞 | 定義 |
|---|---|
| Run | 一次完整挑戰，由 8 個關卡依固定順序組成；任一關失敗即整個 Run 終止 |
| 關卡（Encounter） | 單一棋盤挑戰，具有 Boss HP 與手數預算兩個屬性 |
| 連線 | 玩家的 5 顆（含）以上棋子在橫、直、斜任一方向連續相鄰；6 顆以上視為同一條線 |
| 傷害 | 連線結算對 Boss HP 造成的扣減值，公式見 FR-B3 |
| 手數預算 | 該關玩家可落子的次數上限；使用技能不消耗手數 |
| 遺物（Relic） | 被動常駐效果，購買後在該 Run 剩餘關卡全程生效 |
| 主動技能 | 消耗型道具：使用一次後即從持有中移除 |
| 突變（Mutation） | Boss 關附加的規則修改，僅該關生效 |
| 金幣 | Run 內貨幣，Run 結束即歸零，不跨 Run 累積 |

## 3. 增量切分與範圍

| 增量 | 內容 | 交付判準 |
|---|---|---|
| 增量 A | 效果系統資料驅動化（內部重構，無新玩法） | 現有 PVP 行為零變化，回歸測試全綠 |
| 增量 B | 單關挑戰玩法（無 Run、無商店） | 一關可完整遊玩至勝/敗結算 |
| 增量 C | Run 循環、商店、遺物、Boss 突變 | 一輪 8 關 Run 可完整遊玩 |

**明確不在本文件範圍**（後續增量另立文件）：AI 干擾型對手、meta 解鎖進度、每日挑戰、排行榜、觀戰、PVE 離線單機版。

## 4. 與現有系統的不變式

1. 現有 `GameMode`（LOCAL/ONLINE）×`BattleMode`（NORMAL/SERIOUS_DUEL）的所有規則與 API 行為**完全不變**。
2. 帳號與 JWT 認證沿用現有機制；PVE 僅限已登入玩家遊玩。
3. PVE 不使用 Swap2 開局、不使用 PVP 的「每技能每場限用一次」規則（改依 FR-A2 資料欄位控制）。

## 5. 功能需求

### 增量 A：效果系統資料驅動化

- **FR-A1 效果定義外部化**：現有 6 個技能（HORIZONTAL_SLASH、VERTICAL_SLASH、HEAVEN_EARTH_REVERSAL、PRECISION_SNIPE、SCATTER_SHOT、PIONEER_STAR）與 2 個場地效果（火山噴發、海灘漲潮）的效果，改為「觸發器＋條件＋原子操作序列＋數值參數」的資料定義（JSON 或 DB 表擇一）；引擎端只實作原子操作集：**落子、移除、推移、變換、生成、數值修飾**。
- **FR-A2 使用限制與行動型態資料化**：技能的**使用限制**（每場一次／消耗型／充能型）與**行動型態**（附加於落子／取代落子／獨立行動）皆由資料欄位宣告，不得寫死於程式碼。現有 PVP 宣告為：一般技能＝附加於落子、大絕（HEAVEN_EARTH_REVERSAL、PIONEER_STAR）＝取代落子、全部每場一次。PVE 宣告為：所有技能＝獨立行動、消耗型（見 FR-B5）。
- **FR-A3 隨機性 seed 化**：場地生成（障礙格、隱藏格位置）與所有隨機效果統一使用注入的 seed；**同一 seed ＋ 同一操作序列，必得同一結果**。

### 增量 B：單關挑戰

- **FR-B1 建立單關挑戰**：玩家選擇職業（WARRIOR 或 ARCHER）後建立關卡。棋盤 **11×11**、場地 **PLAIN**（無任何場地效果）、Boss HP **100**、手數預算 **30**。棋盤上只有玩家單方落子，無對手。
- **FR-B2 連線結算**：每次落子或技能結算完成後立即檢查連線。每條連線各結算一次傷害，結算後**該線全部棋子從棋盤移除**，格子恢復可落子。一手最多可在 4 個方向（橫/直/斜/反斜）同時形成多條線：各線獨立結算、各自計分，共用棋子只移除一次；此規則適用於任意 N 條線同時形成（N ≤ 4）。
- **FR-B3 傷害公式**：`傷害 = 基礎分 × 倍率`（向下取整）。基礎分：五連 = **50**，線上每多 1 顆 = **+20**（六連 70、七連 90，依此類推）。倍率初始 **1.0**，修飾來源為遺物與突變（增量 C）。**六連以上的成因說明**：因連線一旦形成即被移除，6+ 連只能由「一手落子（或技能推移）同時連接兩個各未達五連的片段」形成，例：`●●●●＿●●` 於空格落子 → 七連一次結算 90 基礎分。此為刻意設計的高階技巧，需求分析時視為正常路徑。
- **FR-B4 勝敗判定**：Boss HP ≤ 0 → 關卡通過（當下立即結束，不再落子）；手數用盡且 Boss HP > 0 → 關卡失敗。
- **FR-B5 技能使用**：PVE 技能一律為**消耗型＋獨立行動**：發動時不落子、不消耗手數。**大絕（HEAVEN_EARTH_REVERSAL、PIONEER_STAR）在 PVP 的「取代落子」行為不適用於 PVE**，在 PVE 同樣是獨立行動（依 FR-A2 資料宣告切換，引擎不得硬編碼）。使用時點：任兩次落子之間（含該關第一次落子之前），**每個間隔至多使用 1 個技能**。第 30 手落子及其全部連鎖結算完成後立即依 FR-B4 判定，之後不可再使用技能。建關時依職業附贈 1 個技能：WARRIOR 附 HORIZONTAL_SLASH、ARCHER 附 PRECISION_SNIPE。技能持有上限 **3**。技能效果本身造成的棋子移除**不**計傷害（僅連線計傷，增量 C 遺物另有例外）；技能推移棋子後若形成連線，照 FR-B2 正常結算。
- **FR-B6 持久化與續玩**：關卡狀態存於後端；玩家斷線或重新整理後，回到遊戲即從最後一手續玩。
- **FR-B7 關卡結算畫面**：顯示勝/敗、總傷害、剩餘手數、已使用技能清單。

### 增量 C：Run 循環

- **FR-C1 Run 結構**：8 關依固定順序，手數預算每關固定 30。Boss HP 依下表（1.6 倍曲線取整）：

  | 關 | 1 | 2 | 3（Boss） | 4 | 5 | 6（Boss） | 7 | 8（Boss） |
  |---|---|---|---|---|---|---|---|---|
  | HP | 100 | 160 | 260 | 420 | 670 | 1070 | 1710 | 2740 |

- **FR-C2 場地排程**：第 1、3、4、6、8 關為 PLAIN；第 2、5、7 關由 seed 各自 50% 機率決定為 VOLCANO 或 BEACH 的 11×11 變體——可見障礙格 **3–5 個**、隱藏格（噴發／漲潮）**至多 3 個**；BEACH 海浪沿用「每 10 手結算一次」規則（手數以玩家落子計）。**工程註記（明確列為增量 C 工作項）**：現有引擎的場地尺寸與類型硬綁（VOLCANO=15、BEACH=16），11×11 變體是**新增的幾何規格**而非既有能力複用；BEACH 11×11 的海／沙切分明確定義為：初始海側 **5** 行、沙側 **6** 行（奇數高度取海側 = ⌊11/2⌋）。
- **FR-C3 金幣**：Run 起始 0 金幣。通過一關獲得 `10 ＋ 該關剩餘手數` 金幣。金幣不設上限。**經濟基準（供數值驗證，非需求）**：第 1 關 100 HP 在無遺物下最少需 2 條五連 = 10 手，通關獎勵約 10＋20 = 30 金幣，足以購買 1–2 件商品；此為商店定價的錨點。
- **FR-C4 商店**：每關通過後進入商店（第 8 關通關後無商店，直接 Run 結算）。商店固定展示：遺物 ×2、技能 ×1（**僅自玩家職業的 3 個技能中抽取**——WARRIOR：HORIZONTAL_SLASH／VERTICAL_SLASH／HEAVEN_EARTH_REVERSAL，ARCHER：PRECISION_SNIPE／SCATTER_SHOT／PIONEER_STAR；同名技能可重複購買持有，售價一律 **6**）。提供「重抽」（**5** 金幣，三個展示位全部重新抽取，次數不限）與「跳過」。已持有的遺物不會被抽出；持有達上限（遺物 5、技能 3）時對應商品不可購買。
- **FR-C5 遺物清單**（初始池 8 個；效果全部透過 FR-A1 的資料定義實作）：

  | # | 名稱 | 效果（明確定義） | 售價 |
  |---|---|---|---|
  | 1 | 銳刃 | 連線基礎分 +20 | 8 |
  | 2 | 連鎖核心 | 你的技能推移效果連鎖距離 +1 格 | 6 |
  | 3 | 斜行者 | 斜向連線的倍率 +0.5 | 10 |
  | 4 | 火山之心 | 噴發清除的棋子，每顆對 Boss 造成 10 傷害 | 10 |
  | 5 | 防潮堤 | 海浪與漲潮不移動、不移除你的棋子 | 8 |
  | 6 | 節拍器 | 落子計數以**整個 Run 累計**（跨關不重置；例：第 1 關落滿 30 手後，第 2 關第 5 手為 Run 第 35 手）。每逢 Run 累計第 5 的倍數手，倍率 +0.1，加成於該 Run 內永久有效 | 12 |
  | 7 | 回收商 | 因連線移除的棋子累計每 10 顆，手數預算 +1（當關生效） | 10 |
  | 8 | 雙子星 | 一手同時完成 ≥2 條線時，該手總傷害 ×2 | 14 |

- **FR-C6 Boss 突變**（固定配置，不隨機）：
  - 第 3 關「獨眼」：**橫向**連線不結算（不造成傷害、棋子不移除）。
  - 第 6 關「震怒」：玩家每落 5 手，隨機一個有棋子的格子發生噴發，清除該格及周圍 8 格的棋子（此清除不造成 Boss 傷害；持有遺物「火山之心」則照其效果計傷）。
  - 第 8 關「深淵」：每次連線結算完成後，隨機一個空格生成 1 顆**障礙棋子**——不可落子於其上、不可作為連線組成、可被技能推移或移除。
- **FR-C7 Run 終止與結算**：任一關失敗 → Run 終止；玩家亦可主動放棄（視同失敗）。Run 結算畫面顯示：到達關數、全 Run 總傷害、獲得與花費金幣、最終持有遺物/技能。
- **FR-C8 Run 持久化**：同一帳號同時至多 1 個進行中的 Run；建立新 Run 前必須結束（通關/失敗/放棄）現有 Run。進行中 Run 可跨 session 續玩。

## 6. 契約影響概要（供 api.yml / erm.dbml 增量參考，非最終契約）

- 新增 PVE 生命週期操作：建立 Run、查詢 Run 狀態、關卡內落子、使用技能、商店購買／重抽／跳過、放棄 Run。
- 單人模式一律 HTTP request/response，**不新增 WebSocket 通道**。
- 新實體概念：Run、Encounter、遺物持有、技能持有、商店展示（ShopOffer）、seed。
- 現有 PVP 契約（endpoints、schema）**零修改**。

## 7. 非功能需求

- **NFR-1 確定性**：同 seed ＋ 同操作序列 → 同結果，作為測試與問題重現的基礎。
- **NFR-2 效能**：落子結算（含連線檢查、效果結算）API 回應 P95 < 500ms。
- **NFR-3 回歸保護**：增量 A 合併時，現有 PVP 測試套件必須全綠且無行為變更。
- **NFR-4 語言**：所有 UI 文案為繁體中文。

## 8. 已代決策的預設值（如需推翻，請於澄清階段提出）

以下為撰文時代替使用者做的設計決策，皆已寫入上方需求；列出供快速檢視：

1. PVE 棋盤 11×11（非 PVP 的 15×15/16×16）——為壓縮單關時長。
2. 增量 B/C 皆**無對手落子**（純 score attack）；AI 干擾者延後至下一份增量文件。
3. 技能不消耗手數；一手至多用 1 個技能。
4. 六連以上視為一條線並加成基礎分（不拆成多條五連）。
5. Boss HP 曲線採 1.6 倍指數；手數預算固定 30 不隨關數變動。
6. 金幣與遺物不跨 Run 保留（無 meta 進度，屬後續增量）。
7. 突變固定綁定第 3/6/8 關（不隨機），降低首版變因。
8. 商店無限次重抽（只受金幣限制）。
9. 大絕在 PVE 改為「獨立行動、不消耗手數」（PVP 的「取代落子」不適用），由 FR-A2 的行動型態欄位切換。
10. 商店技能池限玩家職業（不可跨職業購買）；同名技能可重複持有。
11. 「節拍器」的落子計數為 Run 全程累計，跨關不重置。
12. BEACH 11×11 為新幾何規格：海側 5 行、沙側 6 行；11×11 支援列為增量 C 工作項。
